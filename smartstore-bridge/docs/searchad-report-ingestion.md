# Offline-composed report ingestion

Reporting registration remains OFF by default (`ATELIER_SEARCHAD_ALLOW_REPORTING_JOBS=false`). Provisioning, credentials, real Customer calls and deployment are outside this increment. `/stats` observations remain provisional. The signed `/report-download` transport is a separate capability; the pinned raw operation inventory remains 126.

An operator registers an owned report intent, then calls `POST /api/v1/searchad/reporting/jobs/{reportJobId}/ingest` with only `customerId`. Archived bytes are available to scoped readers at `GET .../{reportJobId}/content?customerId=...`; no upstream URL is returned. `POST .../{reportJobId}/evaluate` explicitly evaluates policy stability. Recollection selects a generation per Customer/type/statDate instead of adding duplicate daily spend. An identical job/hash keeps its original archived window. Changed bytes revoke prior selected authority. Restabilization requires a valid later generation and explicit evaluation; immutable evidence is never rewritten.

Production storage uses `@aws-sdk/client-s3` and the normal SDK credential provider chain. Configure `ATELIER_SEARCHAD_REPORT_S3_BUCKET`, optional HTTPS `ATELIER_SEARCHAD_REPORT_S3_ENDPOINT`, `ATELIER_SEARCHAD_REPORT_S3_REGION`, and `ATELIER_SEARCHAD_REPORT_S3_PREFIX`. The SDK adapter accepts an injected client for offline contract tests. Raw content is Customer-scoped and SHA256-addressed, checked after write and on read; retention metadata is two years and no purge is implemented. This does not provision or certify provider retention enforcement. Development/test code may inject `LocalReportStorage`; production has no local fallback.

`ATELIER_SEARCHAD_REPORT_INGESTION_REQUIRED=true` makes overall completion readiness fail when ingestion dependencies are unavailable. Ingestion itself always returns unavailable without configured storage and generation policy. Set positive finite `ATELIER_SEARCHAD_REPORT_CLOCK_UNCERTAINTY_MS` (maximum 3600000) and `ATELIER_SEARCHAD_REPORT_ROLLOUT_UNCERTAINTY_MS` (maximum 86400000) to adopt `generation-window-v1`. No default synchronization claim is made. `ATELIER_SEARCHAD_REPORT_MAX_BYTES` defaults to 64 MiB (maximum 256 MiB); redirects are forbidden and response bodies are streamed with size and declared-length checks.

Generation policy assumes the configured local clock bound and a causal connection between a fresh, owned, acknowledged registration and the generated report. These are declared operating assumptions, not measured synchronization or an upstream immutability guarantee. The lower bound is attempt start minus clock uncertainty. The upper bound is download completion plus uncertainty. Attempt, fenced transport initiation, acknowledgment, BUILT observation and completion must be monotonic. Stat `updateTm` is modification metadata only; exact `reportCreatedAt` remains null, supported by the narrow append-only 0011 migration. Master generation time is bounded separately and must fit the owned event window. Date-only notices use KST with configured rollout uncertainty; the entire window must fall strictly on one side. Missing proof quarantines.

A collection slot counts only when the complete widened window fits one KST day. Stabilization requires actual D+1, D+2 and D+3 collections, and a complete selected AD generation whose lower bound is D+3 or later and at least 48 hours after the stat day's end. A late poll cannot age an early registration into evidence. A current generation crossing KST collection days quarantines and revokes prior authority even if historical slots1/2/3 exist. Freshness is measured from the original conservative generation lower bound; future or nonfinite ages are rejected. Evidence observation time retains original download completion, while stabilization time records the distinct evaluation event. Re-evaluation or identical-hash reuse cannot refresh old evidence. Only source-proven VAT-included AD cost can enter v1 spend evidence. Historical pre-2026-03-30 decimal net cost remains net; no invented conversion to gross is applied.

Exact supported formats and pinned source/checksum metadata live in `specs/naver-searchad/report-schemas.json`: AD, AD_CONVERSION, EXPKEYWORD, ADEXTENSION and ADEXTENSION_CONVERSION before/after the 2026-11-16 change, and Campaign, Adgroup (18/19-column AI Ads boundary), Keyword and Ad master. EXPKEYWORD enum 5 remains exact. Other known formats are explicitly unsupported; NAVERPAY_CONVERSION is retired. Unsupported or malformed reports cannot authorize spend. UTF-8 decoding, ordered types, Customer/date/entity checks, exact field count, enum validation and conflicting natural rows are enforced; all rows promote atomically or none do.

Native PostgreSQL acceptance runs in the existing CI workflow with zero skips and checks migrations, HTTP/bootstrap restart, atomic rollback, concurrency, immutable spend evidence, revocation and explicit restabilization. Local tests use synthetic closed upstreams only. No successful local synthetic run is a live verification claim.
