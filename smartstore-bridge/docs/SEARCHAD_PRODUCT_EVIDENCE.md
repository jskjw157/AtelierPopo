## Composition and authority

`bootstrapSearchAdCompletionRuntime` creates providers using the already configured CommerceOperationGateway and the documented GET-only Cafe24AdminClient. Cafe24 uses the existing config, token store and token provider. No collection occurs during bootstrap. Runtime operation tracking drains all pending product work before releasing the borrowed PostgreSQL pool. No worker schedule, advertisement execution route or operational gate is added.

An authenticated Customer Admin must bind a channel before mapping a canonical product. Binding identity includes the current SearchAd spec SHA/credential fingerprint/origin and a hashed provider account/credential/contract identity. Binding means explicit local authorization to the existing server-configured account; it does not verify remote ownership. All method/path/account/credentials and evidence identities are built by the server. Rotating the source or SearchAd identity invalidates selection until a current binding/mapping exists. Original Commerce read/verification gates still apply. Default unverified-operation gate denial produces missing evidence, with no upstream call.

Admin routes: `POST /api/v1/searchad/customer-channel-bindings`, `/product-mappings`, `/product-costs`. Operator: `POST /api/v1/searchad/product-evidence/collect`. Reader: `GET /api/v1/searchad/profitability/products/{haarProductId}?customerId=...&since=YYYY-MM-DD&until=YYYY-MM-DD`. Exact request bodies and role documents are published in completion OpenAPI. Unknown fields such as accountId, operationId, path, confidence, trusted, liveVerified or provider are rejected.

Mappings and costs are immutable effective-dated revisions. Latest revision selection happens before expiry checks so an expired newer revision never revives an older one. Shared ads require explicit positive decimal weights covering the linked products and summing exactly to one. Manual weights are still unverified; Task8 never assigns shared advertising spend or declares Auto eligibility. Costs are manual estimates, their source/reason text is stored as hashes, and variant inputs must belong to the canonical product. Catalog costs follow effective canonical source/variant links with source-specific identity and remain unverified. Import snapshot summaries expose only safe state/stock and snapshot identity, not raw content.

## Persistence and quality

Observations are immutable, scoped to Customer+canonical product+channel+binding+identity+date range+capability+collection time. Rows are positively projected again at persistence: numeric/date/enum values and hashes only. Buyer names, addresses, contacts, raw order/claim IDs, URLs and credentials never enter new evidence rows or public summaries. Provider errors become bounded missing codes; raw exception bodies are discarded. Provider-owned Cafe24 logging discards upstream metadata URLs.

Order and claim duplicates are deduplicated by scoped source references, conflicting duplicates make the collection incomplete. Repeated identical observations at an identical clock are idempotent; later collections are separate immutable generations. Summary selection chooses only the latest observation per channel/capability for the exact range and current identity; it never adds recollections together. Product evidence over 15 minutes is marked stale. Missing values remain null, including an empty settlement result. Mapping validity that does not cover the requested historical range is explicit partial. Summary quality is unknown without usable observations and partial otherwise. Contribution, aggregate net revenue and settlement totals remain null; profitability arithmetic/reconciliation is Task9. `liveVerified` and `autoEligible` are false for every Task8 result.
