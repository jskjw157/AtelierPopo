# SearchAd VPS 로컬 원본 저장 + Mac 외장디스크 백업 설계

## 1. 사용자가 선택한 목표

S3 신규 도입 없이 Hostinger VPS가 SearchAd 보고서 원본을 저장한다. 24시간 켜 둘 Mac에 연결한 10TB 외장디스크는 별도 백업 대상으로 사용한다. Mac 장애가 즉시 VPS의 원본 저장 실패로 이어지지 않게 한다. 사용자가 코딩 담당을 이 ChatGPT에게 이어받도록 요청했다.

10TB는 사용자가 알려준 전체 용량이며, 실제 여유 공간·디스크 종류·파일시스템·볼륨 UUID·마운트 경로는 아직 확인하지 않았다. 과거 등장한 `/Volumes/X9 Pro`를 이 디스크라고 추정하지 않는다.

기존 Commerce, 다른 애플리케이션의 DB/볼륨, Mac의 기존 자료를 변경하지 않는다. 포맷·삭제·main 병합·후보 앱 배포·실계정 호출·SearchAd 활성화는 이 설계의 승인이 아니다.

- 같은 운영 문서는 S3 저장소와 정기 외부 백업이 아직 준비되지 않았다고 기록한다. 이 설계는 그 중 보고서 저장 방식만 A 방식으로 바꾸는 후속 작업이다.

## 3. 구성과 데이터 흐름

VPS의 전용 영구 저장 디렉터리에 보고서 원본을 먼저 저장하고, 파일 검증이 끝난 뒤 기존 PostgreSQL ingestion 흐름에 메타데이터를 기록한다. Mac은 제한된 읽기 전용 SSH 경로로 완성된 백업 세트를 가져온다. Mac 외장디스크를 VPS에서 직접 마운트하지 않는다.

VPS에는 원본과 백업 내보내기 영역을 분리한다. Mac에는 기존 자료와 구분되는 전용 백업 하위 디렉터리를 사용한다. 실제 절대경로는 운영자가 확인한 볼륨과 용량을 바탕으로 별도 설정하며 현재 존재하는 경로라고 문서에 만들어 넣지 않는다.

기존 S3 adapter는 삭제하지 않는다. 기본 동작을 임의 변경하지 않고, 명시적으로 선택한 로컬 운영 프로필만 새 경로를 사용한다. 개발용 LocalReportStorage를 무조건 운영용으로 승격하지 않는다.

## 4. 운영용 로컬 저장 계약

기존 Customer/hash 키와 put/get 호출 계약을 재사용하는 별도 운영용 로컬 adapter를 추가한다. 구성 검증과 native 파일시스템 검증을 거친 인스턴스만 운영 프로필로 선택할 수 있다.

- 전용 절대경로, 기대 저장소 식별 marker와 실제 mount/device를 확인한다. mount 누락 시 컨테이너 임시 디스크나 다른 경로로 대체하지 않는다.
- Customer/hash 키의 엄격한 검증, 루트 밖 접근·심볼릭 링크 우회 거부, 제한된 파일/디렉터리 권한을 적용한다.
- 임시 파일에 끝까지 기록하고 파일 무결성을 확인한 뒤 같은 파일시스템에서 원자적으로 확정한다. 내구성 동기화와 디렉터리 갱신을 확인한 뒤 성공을 반환한다. 미완성 파일은 정상 리포트로 보이지 않는다.
- 동일 키 동시 저장은 정상 완성본 하나로 수렴해야 한다. 기존 파일의 해시가 다르면 덮어쓰기·삭제로 복구하지 않고 오류와 명시적 복구 필요 상태를 남긴다.
- 디스크 부족, 읽기 전용 전환, mount 누락, fsync 실패, 권한 오류, 손상은 성공으로 보고하지 않는다. 하류 수익성/자동화에 가짜 증거를 공급하지 않는다.
- generationPolicy, identity, Customer, 기존 ingestion/activation/send 경계는 유지한다. 저장소 선택이 광고 실행 권한이 되지 않는다.

영구 로컬 디스크는 관리형 Object Storage와 동일한 내구성 또는 변경불가 보존 보장을 제공한다고 주장하지 않는다. 운영 준비 판정에는 실제 mount·재시작·백업·복구 검증이 추가로 필요하다.

## 5. 백업 계약

단순 미러링 대신 원본 삭제가 백업에 전파되지 않는 날짜별/세대별 백업을 사용한다. 자동 삭제와 보관본 정리는 초기 버전에 넣지 않는다. 원본 2년 보관은 기존 프로젝트 정책으로 유지하되, 실제 사용량 측정 없이 10TB로 보장된다고 주장하지 않는다.

VPS가 일관된 PostgreSQL logical dump와 같은 DB snapshot에서 참조되는 원본 목록/해시를 포함한 백업 manifest를 만든다. 참조 원본이 없거나 손상되면 세트는 완료되지 않는다. 작업 중 새로 생성된 원본이 추가로 복사되는 것은 허용하지만 DB snapshot이 참조하는 원본 누락은 허용하지 않는다. 활성 DB 데이터 디렉터리를 파일 복사하는 방식은 쓰지 않는다.

Mac은 완성 marker가 있는 세트만 전송받아 원본과 dump의 해시를 검증하고, 모든 필수 파일이 확인돼야 로컬 완료 기록을 남긴다. 중단된 전송은 재시도할 수 있지만 완료 기록을 미리 만들지 않는다. 중복 작업은 잠금으로 겹치지 않게 한다.

Mac의 실제 외장 볼륨 UUID/마운트 경로/쓰기 가능 여부/여유 공간을 매번 확인한다. 디스크가 빠지면 해당 실행은 실패로 남기고 Mac 내부 SSD의 대체 디렉터리에 쓰지 않는다. 기존 자료 삭제·포맷은 하지 않는다.

전송은 호스트 키를 검증하는 암호화 연결을 사용한다. 백업 전용 계정은 완성된 내보내기 데이터만 읽고, 앱 환경변수·API 키·TLS 개인키·원본 삭제 권한은 갖지 않는다. 비밀값은 Git/로그/manifest에 넣지 않는다. 보고서/DB의 민감한 내용은 암호화된 외장 볼륨 또는 검증된 암호화 백업 저장 방식으로 보호한다. 파일시스템을 바꿔야 할 경우 자동 포맷하지 않고 중단한다.

제안 주기는 매시간 백업이다. 백업 지연과 원본 저장 readiness는 별도 상태로 보고한다. Mac 일시 중단 시 원본 수집은 VPS의 안전한 여유 공간 내에서 계속할 수 있지만, 마지막 검증된 백업 이후 데이터는 VPS 전체 유실 시 복구되지 않을 수 있다. 매시간은 목표 복구 시점이며 성공을 검증하지 않은 실제 보장값은 아니다.

## 6. 복구 및 안전한 재시작

복원은 격리된 테스트 DB/디렉터리에 수행한다. 0015 migration metadata, 참조 원본 전체 해시, Customer 연결, 승인·실행·unknown 상태를 확인한다. 백업 이후 실제 원격 광고 변화가 있을 수 있으므로 복구된 앱의 광고 변경/worker/Canary 게이트는 OFF로 시작한다. 기존 read-only reconcile과 운영 검토 전에는 소비된 승인·위험 예산·실행 intent를 재사용하지 않는다.

앱/DB뿐 아니라 비밀설정과 배포 구성까지 포함한 전체 재해복구는 별도 운영 절차이다. 이 백업 세트를 전체 시스템 복구 완료로 확대 해석하지 않는다.

## 7. 구현 분리와 검증 기준

첫 증분은 운영용 로컬 adapter, 설정/factory 선택, 기존 runtime의 엄격한 준비 상태와 파일 무결성·동시성·장애 테스트이다. 두 번째 증분은 백업 세트/export와 Mac pull/mount 확인·검증·실패 기록이다. 세 번째는 실제 두 장비에서 별도 승인하에 경로 확인 및 복구 리허설이다.

파일 후보: `src/naver/searchad/reporting/`의 새 adapter/config 선택, 기존 storage factory 연결부, `ops/searchad/` 백업 도구/설정 템플릿, 저장소/백업 focused tests, 해당 CI 및 runbook. 0001–0015 migration과 기존 광고 제어 기능은 이 작업의 수정 대상이 아니다. 구체 파일과 명령은 설계 검토 후 구현 계획에서 고정한다.

반드시 검증할 실패 조건은 부분 쓰기/프로세스 중단, 중복 put, 오염 파일, 디스크 부족, 잘못된 mount, symlink 탈출, 백업 전송 중단, 외장디스크 분리, dump/manifest 불일치와 잘못된 Customer이다. S3 경로와 기존 전체 회귀도 유지한다. native PostgreSQL 미실행/건너뜀은 성공으로 집계하지 않는다. 테스트용 합성 데이터는 실제 광고 증거가 아니다.

## 8. 이번 인수 작업에서 관측한 실행 환경

GitHub connector로 현재 PR/소스/CI 조회 및 별도 브랜치 생성이 가능했다. ChatGPT 작업 컨테이너는 Linux/Node 22.16.0이며 사용자의 Mac이 아니다. 직접 git clone은 GitHub DNS 해석 실패로 완료되지 않았다. 연결된 Gram Coding Agent health 요청은 `tunnel_client_not_seen`으로 실패했다. 이 결과는 사용자의 Mac이나 VPS가 꺼졌다는 뜻이 아니다. 현재 세션에서 실제 Mac 디스크나 VPS 접속 성공을 주장하지 않는다.

제품 코드 변경, native PG 재실행, Mac 백업 설치, VPS 변경 및 새 테스트 성공은 아직 없다. 새 코드 검증은 GitHub CI 또는 연결이 확인된 격리 실행 환경에서 수행하고 정확한 SHA와 결과를 별도로 기록한다.

## 9. 운영 적용 전 확인할 입력

실제 10TB 외장 볼륨 UUID/경로/파일시스템/여유 공간, VPS 원본·export 여유 공간, 검증된 SSH 접속 및 호스트 키, 백업 전용 읽기 권한, 암호화/잠금해제 방식과 실패 알림 경로가 필요하다. 이 값이 미확인이어도 코드와 합성 테스트 설계는 진행할 수 있지만 실제 설치·운영 검증은 완료할 수 없다.

이 문서 승인은 저장/백업 코드의 상세 구현 계획을 작성하기 위한 승인이다. 실제 장비 설정·후보 앱 배포·main 병합·광고 호출 또는 계정 활성화 승인이 아니다.
