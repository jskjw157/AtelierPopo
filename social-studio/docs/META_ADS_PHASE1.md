# HAAR Meta Ads — 구현 및 운영 경계

## 제공 기능

`/ads`에서 광고 전용 Meta OAuth, 광고계정 조회·선택, 캠페인/광고세트/광고 조회, 기간별 성과 동기화, 로컬 초안, 승인 요청을 제공합니다. 기존 Page/Instagram 게시용 토큰은 변경하지 않습니다.

상품을 선택하면 구매 URL을 가져옵니다. 사진·상품·문구·타겟·기간·예산·광고계정은 승인 요청에 고정됩니다. 기존 게시물 소스는 **사진과 문구를 복사한 별도 광고**이며 좋아요·댓글을 승계하지 않습니다. 현재 생성 형식은 **단일 이미지**입니다. 영상과 캐러셀은 거절하며 다른 형식으로 몰래 바꾸지 않습니다.

읽기와 로컬 초안은 Meta 집행을 변경하지 않습니다. 시작·중지·재개·예산 변경은 요청마다 정확한 해시와 사용자 확인이 필요합니다. 처음 생성한 캠페인·광고세트·광고는 모두 중지 상태이며, 이미지/링크/문구/계정/일정/예산/지출 한도를 재조회한 후 캠페인을 마지막에 활성화합니다.

## 배포 시 기본 상태

```dotenv
META_ADS_WRITES_ENABLED=false
HAAR_TOOL_BEARER_TOKEN=
HAAR_TOOL_ACTOR_ID=
```

- `META_ADS_WRITES_ENABLED`는 정확히 `true`일 때만 서버 집행 게이트를 엽니다. 이것이 승인을 대체하지 않습니다. 초기 운영에서는 false를 유지합니다.
- 기존 Meta 앱 ID/비밀키/Graph 버전/콜백을 재사용합니다. 기존 `META_SCOPES`를 광고 권한으로 덮어쓰지 않습니다.
- **광고 관리 → Meta 광고 권한 연결**에서 `ads_read,ads_management`에 별도로 동의해야 합니다. 환경변수에 이름을 적는다고 권한이 부여되지 않습니다.
- 앱의 Marketing API 사용 설정, 접근 수준, 운영자/광고계정 역할은 Meta 대시보드에서 충족해야 합니다. 별도 Business 자산 경로가 필요하면 그때 최소 권한을 추가합니다.
- 연결 후 목록 조회 → 운영할 광고계정 선택 → 읽기 연결 테스트 → 성과 동기화 순서로 확인합니다.
- `managementGranted`는 토큰 권한 표시일 뿐 실제 광고 생성 성공을 의미하지 않습니다. `writePreflightPassed`도 읽기 기반 사전 확인입니다.

## 예산과 추적

지원 예산 통화는 KRW/JPY(기본 단위), USD/EUR/GBP/AUD/CAD/SGD/HKD(100분의 1 단위)입니다. 다른 통화는 추정하지 않고 차단합니다. 예산을 반올림하지 않으며 소수 자릿수나 안전 정수 범위를 벗어나면 거절합니다. 실제 계정에서 원시 예산을 대조한 뒤 집행 게이트를 열어야 합니다.

일예산은 평균 예산이므로 일예산×기간을 확정 상한으로 안내하지 않습니다. 기간 전체 상한이 목적이면 총예산을 선택합니다. 일예산의 별도 캠페인 지출 한도는 Meta가 허용하는 최소값·조합에 따라 검증되며 서버가 임의로 상향하지 않습니다. 세금/수수료는 광고 예산과 별도입니다.

구매 목표는 접근 가능한 픽셀을 확인해야 합니다. 픽셀 ID가 있다는 것만으로 Purchase 이벤트/구매액 측정이 정상이라는 뜻은 아닙니다. 실운영 전 이벤트 설정을 확인합니다. 없는 구매/ROAS 지표는 0으로 만들지 않습니다. CPC/CPM 등의 소수 값도 정수로 반올림하지 않습니다. 목록 조회는 페이지 상한을 넘기면 일부 데이터로 전체 합계를 만들지 않고 오류를 반환합니다.

## 실패와 재실행

외부 쓰기 전에 승인 요청을 DB에 `executing`으로 커밋하고 광고계정 단위 실행 잠금을 잡습니다. 생성된 외부 ID를 단계마다 저장합니다. 같은 요청의 중복·동시 실행은 거절합니다.

응답이 불명확하면 `verification_required`로 남기고 재생성하지 않습니다. **Meta 결과 재조회**는 GET만 수행합니다. 최종 활성화의 응답만 유실된 경우 일치하는 실제 상태를 확인해 완료 기록을 복구할 수 있습니다.

부분 생성/실제 검증 오류가 발생한 요청은 자동으로 복구·재시도하지 않습니다. 확인되지 않은 계정에서는 후속 집행을 차단합니다. 운영자가 Meta에서 생성된 중지 객체와 실행 원장을 대조해야 합니다. 이 기능은 분산 네트워크의 완벽한 exactly-once를 보장하는 것이 아니라, 중복 발송 방지와 불명확 상태의 명시적 확인 절차입니다.

## ChatGPT/MCP 경계

`POST /mcp`는 공식 MCP SDK의 Streamable HTTP 프로토콜로 다음 **읽기 전용** 도구를 제공합니다.

- `haar_ads_status`, `haar_ads_accounts`, `haar_ads_campaigns`
- `haar_ads_insights` (저장된 기간별 성과)
- `haar_ads_drafts`, `haar_ads_pending_actions`

별도 랜덤 Bearer 자격증명(최소 32자)과 서버에 지정한 활성 owner ID가 있어야 합니다. Meta 토큰, 세션 쿠키, 앱 비밀키를 연동 비밀번호로 쓰지 않습니다. 브라우저 Origin/Host 검사와 매 호출의 DB 역할 검사를 수행합니다.

**이 서버 구현/프로토콜 테스트가 사용자의 ChatGPT에 앱이 등록됐다는 뜻은 아닙니다.** 사용하는 ChatGPT 클라이언트의 인증 방식/플랜/워크스페이스 정책을 실제로 확인해야 합니다. 현재 전송 계층은 Bearer 방식이며 OAuth만 허용하는 클라이언트에는 별도 OAuth 게이트웨이 구성이 필요합니다. 인증을 없애서 연결하지 않습니다. 대화에서의 초안 작성·승인·집행 도구는 노출하지 않았습니다. 해당 작업은 현재 보호된 Social Studio 화면/API를 사용합니다.

## 검증

개발 DB는 운영 DB와 분리합니다. 통합 테스트는 localhost의 이름이 `_test`로 끝나는 DB만 허용하며 테스트마다 무작위 schema를 생성/삭제합니다.

```bash
cd social-studio
npm ci
ADS_TEST_DATABASE_URL=postgres://test:TEST_PASSWORD@127.0.0.1:5432/haar_ads_test npm test
npm run check:syntax
npm run build
python -m unittest discover -s test -p 'test_*.py'
```

2026-09-23 로컬 확인: 115개 Vitest 테스트 통과(실제 PostgreSQL, HTTP/MCP, 실제 서버 부팅, React DOM 포함). 기존 로그인/비밀번호/보안 테스트 유지. Meta 쓰기는 주입된 공급자 시뮬레이터로만 검증했습니다. 작성자 자체 리뷰이며 독립 리뷰어 검토는 아닙니다.

### 아직 실운영 확인이 필요한 항목

Meta 광고 권한 재동의, 실제 광고계정/통화/시간대/픽셀 조회, Meta의 중지 상태 생성 및 계정별 정책 검증, ChatGPT 클라이언트 인증/등록, 최초 유료 집행의 구체적 승인. CI/배포 테스트는 실제 유료 광고를 시작하지 않습니다.
